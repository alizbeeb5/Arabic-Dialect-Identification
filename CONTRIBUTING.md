# Contributing

Use a focused branch for an experiment or code change. Record the exact command and checks in the pull request, and have a teammate review it before merging into `main`.

For an experiment, record the model and code revisions, manifest hashes, seed, optimizer updates, evaluation cohort, label space, coverage, and the time scope measured. Document when external development labels or earlier results influenced the design.

Commit source code, settings, and aggregate evidence. Store downloaded data, transcripts, checkpoints, caches, and credentials separately. Keep generated runs under `runs/`.
